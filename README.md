# 邻里盘 · Windows SMB 多人共享门户

把服务部署在 **A 机器（Windows）**，就能由 A 主动连接 B、C 等机器的 Windows 共享目录；所有内网用户从浏览器访问 A 的文件门户、看到统一清单并下载文件。

数据流为：`B 机器共享目录 → A 机器服务 → 内网用户浏览器`。

## 启动

在 A 机器安装 Python 3.9 或更新版本后，于项目目录执行：

```powershell
$env:LAN_FILE_HUB_ADMIN_TOKEN = "请替换为足够长的管理员口令"
python server.py --port 8080
```

访问 `http://A机器IP:8080`，例如 `http://192.168.1.20:8080`。

服务会创建 `data/lan_file_hub.db` 保存共享目录信息，但**不会保存 SMB 密码**。密码由 Windows 凭据管理器按运行服务的 Windows 账户保存。

## 添加 B 机器的共享目录

在“共享管理”中填写：

- **共享服务器 IP / 主机名**：如 `192.168.1.22` 或 `FILE-SERVER`
- **共享文件夹名称**：B 机器在共享设置中公布的名称，例如 `设计资源`
- **SMB 用户名和密码**：只填写拥有 B 机器该共享目录读取权限的用户名，例如 `zhangsan`；服务会自动按 `共享服务器IP\\zhangsan` 连接。不要填写 `IP\\共享名`。

服务会创建并验证等价于 Windows 网络发现中的路径：`\\192.168.1.22\\设计资源`。验证成功后，A 会扫描目录并向所有访客展示文件。

文件页只展示共享根目录的一级文件和一级文件夹；点击一级文件夹会生成 ZIP 并下载完整目录。目录分析也只统计这些一级项目，不递归扫描子目录。

若共享目录就在运行服务的同一台 Windows 机器上，仍可填写该机器的 IP；服务会以启动 `server.py` 的 Windows 账户访问该本机共享。

## 前提与安全

- B 机器需启用“文件和打印机共享”，其防火墙要允许 SMB；共享权限和 NTFS 权限都应授予该账户读取权。
- Windows 后台任务必须以同一个 Windows 账户运行，否则无法读取该账户的凭据管理器记录。
- 每个服务器主机建议仅使用一个 SMB 账号，避免 Windows 同时用不同凭据连接同一主机导致冲突。
- 管理员口令和 SMB 密码会经过浏览器提交；正式部署应使用内网 HTTPS（IIS/Nginx 反向代理）并仅向受信任人员开放管理页。
- 删除共享目录只会删除本系统的登记信息，不会删除 B 机器上的文件或 Windows 凭据。

## Linux 说明

本版本的“IP + 用户名 + 密码”自动连接采用 Windows 凭据管理器，因此需部署在 Windows。若 A 是 Linux，请先用 `mount.cifs` 将 B 的 SMB 目录挂载到本机；如需要 Linux 端在网页中直接管理 SMB 凭据，需要另行接入系统密钥环或 SMB 客户端。
